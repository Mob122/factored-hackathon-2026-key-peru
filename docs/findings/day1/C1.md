### Problems the dictionary does not declare

1. **Branch FKs are broken.** `customers.registration_branch_id` has 100.00% orphans, with 149,995 distinct well-formed IDs that point nowhere; `service_agents.assigned_branch_id` has 99.76% orphans, with 831 distinct well-formed IDs that point nowhere. Registration branch and agent branch cannot be joined.
2. **`complaints.affected_product_id` is not owned by the complaining customer** in 100.0% of 44,570 rows (shuffled baseline 100.0%). The product link is random, so complaint to product to transactions cannot be traced (relevant for Track A). `digital_events.product_id` belongs to its customer in 24.0% of rows (baseline 24.0%), so that link is partial.
3. **Customer registration dates are unrelated to activity.** 18.8% of transactions predate the customer's registration_date, against a shuffled baseline of 18.7%. The same holds for every fact table. Do not use tenure = event - registration_date as a feature without flagging this.
4. **`complaints.origin_interaction_id` is 100% null**, so B4 cannot use the declared link and must fall back to matching by customer and date.
5. **Currency.** MXN never appears. Mexican products are USD (200,398), while Colombia and Argentina use local currency plus some USD. Every transaction inherits its product's currency.
6. **Nulls rendered into text**: `campaign_sends.subject` (38,142 rows), e.g. `¡Oferta especial en nan!`.

**Consequence (from 'Si falla'): document the gaps and adjust the contracts.** The contracts are at the end of this report and in `docs/findings/day1/C1_contracts.json`. For `03_primary`:
- Dedup: only a uniqueness assertion is needed; no rows to drop today.
- Nulls: follow the structural rules per column, not a blanket 5%.
- Labels: map Spanish labels to the dictionary enums, or accept them.
- Broken branch FKs: flag them.
- Partitions: select on the event timestamp, not process_date. process_date is a business day with a cutoff, so date-sliced features must be computed from event time. Surveys can land in a partition before they happen, which is a leakage risk for time splits.

## (b) Nulls

NOT NULL violations: 1 (`call_transcripts.duration_seconds` 14.0%). Blank or null-like strings ('', 'nan', 'None', 'NULL', 'N/A', '-') stored as whole values: none, so nulls are real SQL NULLs. Nulls rendered inside text: `campaign_sends.subject` (38,142).

How to read the tables below:
- **class**:
  - `structural`: another column predicts the null almost perfectly (>= 98% of the impurity explained).
  - `co-null`: the column is mostly null together with another column's null.
  - `structural + random`: always null for some values of the explainer (groups of 30 rows or more), and randomly null elsewhere.
  - `random`: nothing explains it.
- **residual**: the random-null rate outside the always-null groups. Compare it with the declared 5%.
- **by explainer / by month**: binomial dispersion index D of the residual null rate across the explainer's groups and across event months. Under the null baseline (nulls independent of the grouping), D ~ 1 with sd sqrt(2/(G-1)). |z| < 3 reads as generator noise. About 100 tests run here, so an isolated |z| of 3-4 is expected by chance.

For every typed column and every key column, each raw value was reduced to a shape: digit runs -> `9`, letter runs -> `a`, IDs -> prefix + length, booleans kept verbatim. - *every file*: present in every file.
- *sporadic*: missing from some files but spread over the whole period (typically rare values).
- *time-bounded*: first or last seen more than 45 days inside the table's span. Only this one counts as drift.
